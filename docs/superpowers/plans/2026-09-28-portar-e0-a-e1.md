# Portar la E0 como base del backend E1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el backend E1 (`G5ArquiSis/backend`) vuelva a cumplir los requisitos no variables de la E0 en producción, reutilizando el código de la E0 (`master` + `connector`) y desplegándolo por el pipeline ECR + SSM ya existente, detrás de Nginx con HTTPS en `melchort.me`.

**Architecture:** El esqueleto `app/` del backend se reemplaza por `master/` (FastAPI + Postgres, `/history`, `/events`, `/health`) y `connector/` (aio-pika → HTTP POST a master) de la E0, sin cambios de código. El CI construye dos imágenes (`energyshark-master`, `energyshark-connector`) y las despliega en la EC2 con un compose de producción de tres servicios (`postgres`, `master`, `connector`). Nginx en el host (RNF3 E0) termina TLS con el certificado Let's Encrypt existente y hace proxy a `master` en `127.0.0.1:8000`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy async + asyncpg, aio-pika, httpx, pytest + pytest-asyncio, Docker Compose v2, GitHub Actions (OIDC), AWS ECR / SSM / IAM, Nginx 1.24, certbot.

**Spec:** Requisitos no variables de `Enunciado_E0.pdf` (RF1–RF4, RNF1–RNF7, Docker-Compose RNF1–RNF3), exigidos por `Enunciado E1_v1.1.pdf` § "Meta: sobre la entrega": *"Deben tener los requisitos no variables de la E0 operativos para esta entrega."* Decisiones acordadas con el usuario en la sesión del 2026-09-28: portar el código de la E0; una sola réplica de `master`.

- [ ] **Step 2: Reemplazar el job `deploy` del workflow**

En `.github/workflows/deploy.yml`, reemplazar desde `  deploy:` hasta el final por:

```yaml
  deploy:
    needs: test
    # Sin las variables de AWS configuradas, el deploy se salta en vez de fallar.
    if: github.ref == 'refs/heads/main' && github.event_name != 'pull_request' && vars.AWS_ROLE_ARN != ''
    runs-on: ubuntu-latest
    # Dos deploys a la vez podrían dejar la EC2 con una mezcla de versiones.
    concurrency:
      group: deploy-backend
      cancel-in-progress: false
    permissions:
      contents: read
      id-token: write # OIDC: GitHub obtiene credenciales temporales sin access keys guardadas
    env:
      AWS_REGION: ${{ vars.AWS_REGION }}
      EC2_INSTANCE_ID: ${{ vars.EC2_INSTANCE_ID }}
    steps:
      - uses: actions/checkout@v4

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ vars.AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}

      - id: ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build y push a ECR (master y connector)
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
        run: |
          for service in master connector; do
            REPO="$REGISTRY/energyshark-$service"
            docker build -t "$REPO:$GITHUB_SHA" -t "$REPO:latest" "./$service"
            docker push "$REPO:$GITHUB_SHA"
            docker push "$REPO:latest"
          done
          echo "MASTER_IMAGE=$REGISTRY/energyshark-master:$GITHUB_SHA" >> "$GITHUB_ENV"
          echo "CONNECTOR_IMAGE=$REGISTRY/energyshark-connector:$GITHUB_SHA" >> "$GITHUB_ENV"

      - name: Deploy en EC2 vía SSM
        run: |
          # El compose viaja dentro del comando para que la EC2 siempre use el de este commit.
          COMPOSE_B64=$(base64 -w0 deploy/docker-compose.prod.yml)
          COMPOSE="docker compose --env-file .env --env-file release.env -f docker-compose.prod.yml"
          jq -n \
            --arg compose_b64 "$COMPOSE_B64" \
            --arg master "$MASTER_IMAGE" \
            --arg connector "$CONNECTOR_IMAGE" \
            --arg compose "$COMPOSE" \
            '{commands: [
              "set -eu",
              "cd /opt/energyshark",
              "test -f .env || { echo \"falta /opt/energyshark/.env\"; exit 1; }",
              "echo \($compose_b64) | base64 -d > docker-compose.prod.yml",
              "echo MASTER_IMAGE=\($master) > release.env",
              "echo CONNECTOR_IMAGE=\($connector) >> release.env",
              "\($compose) pull",
              "\($compose) up -d --remove-orphans --wait --wait-timeout 180",
              "docker image prune -f"
            ]}' > commands.json

          COMMAND_ID=$(aws ssm send-command \
            --instance-ids "$EC2_INSTANCE_ID" \
            --document-name AWS-RunShellScript \
            --comment "deploy ${GITHUB_SHA::7}" \
            --parameters file://commands.json \
            --query Command.CommandId --output text)

          # Espera hasta ~5 minutos; el waiter de la CLI se rinde antes de que termine un pull lento.
          for _ in $(seq 1 60); do
            STATUS=$(aws ssm get-command-invocation --command-id "$COMMAND_ID" \
              --instance-id "$EC2_INSTANCE_ID" --query Status --output text 2>/dev/null || echo Pending)
            case "$STATUS" in Pending|InProgress|Delayed) sleep 5 ;; *) break ;; esac
          done

          aws ssm get-command-invocation --command-id "$COMMAND_ID" --instance-id "$EC2_INSTANCE_ID" \
            --query '[StandardOutputContent, StandardErrorContent]' --output text
          echo "Estado del deploy: $STATUS"
          test "$STATUS" = "Success"
```

`--remove-orphans` elimina el contenedor `api` y `db` del esqueleto anterior.
